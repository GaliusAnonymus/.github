# Security Policy

## Reporting a vulnerability

**Please do not report security vulnerabilities in public issues, discussions or pull requests.**

Report them privately through GitHub's **private vulnerability reporting**:

1. Open the affected repository on GitHub.
2. Go to the **Security** tab and click **Report a vulnerability**. The direct link is `https://github.com/<owner>/<repo>/security/advisories/new`.
3. Describe the issue, the affected version or commit, the steps to reproduce it and the impact you expect.

If a repository does not show the **Report a vulnerability** button, open a regular issue that **only** asks the maintainer [@RaCzKoViC](https://github.com/RaCzKoViC) to enable private reporting. Do not include any details of the vulnerability in that issue.

## What to expect

- An acknowledgement, normally within **7 days**.
- An assessment and, where confirmed, a fix or mitigation plan. Coordinated disclosure goes through a GitHub Security Advisory, and you are credited unless you ask not to be.
- Please give us a reasonable amount of time to release a fix before any public disclosure.

## Supported versions

Unless a project states otherwise, only the **latest release** and the **default branch** receive security fixes.

## Scope

In scope: the source code, build and release workflows, and published artifacts of the repositories in this organization and of the projects linked from the [organization profile](https://github.com/GaliusAnonymus).

Out of scope: vulnerabilities in third-party dependencies that are already publicly known (report those upstream), as well as social engineering and denial-of-service testing against GitHub itself.
